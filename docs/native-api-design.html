rust-kap · kap-core · RFC

Native Rust API for Kap primitives

A trait + registry that lets you write a Kap builtin in one Rust file — no 16 k-line evaluator.rs patch, no two-gate dance, no 300 KB diff on every edit. Scalar-extension, rank, and error text are handled once; you implement the element logic.

01 Why a new API is needed

The port is conformance-complete (2987/0/0 value-verified), but the way a primitive is added has not scaled with it. Every builtin — from ⍴ to jvm:callMethod — is a branch in a single evaluator.rs ~16 k LOC match. The file echoes a ~300 KB diff on every patch, and a new symbol must be threaded through three places that must stay in sync.

Current cost of one builtin

  • parser.rs::is_known_fn / is_primitive_op — parse-time gate
  • evaluator.rs::is_primitive_name — eval-time gate (two-gate rule)
  • evaluator.rs::eval_apply — the actual arm (often 50–200 LOC)
  • Optional: is_secure_gated, docs, curated_kap_parity row

Miss one gate and the symbol parses but “unknown function” at runtime, or vice-versa. The XmlParserTest 9/9 fix touched three gates plus four symbol-intern sites.

What “native” should mean

  • One file, one trait impl — the builtin lives next to its tests.
  • Parser + evaluator gates are derived from registration, not duplicated.
  • Rank, scalar-extension, and AplError::Runtime message shape are handled once in a shared layer.
  • Adding my:mean does not require opening evaluator.rs.
!
Design constraint — do not break the 2987
Any new registry must be a strict superset of the current match. The migration is mechanical: each existing arm becomes a NativeFn impl with identical oracle text, and the old match becomes a registry lookup with the same two-gate semantics.

02 How evaluation works today

The parser gate and the evaluator gate must list the same names. Today that is a manual copy-paste; drift shows up as a confusing half-error (parses but “unknown function” or vice-versa).

03 Goals & non-goals

Goals

  • One-file builtins. kap-core/src/native/tally.rs defines ≢ end-to-end (name, rank, help, impl, tests). No other file touched.
  • Derived gates. Parser + evaluator learn known names from the registry; no hand-maintained lists.
  • Rank & scalar-extension once. A ScalarFn helper handles Str-as-vector and rank-0/1 broadcast so each arith builtin is ~10 lines of element logic.
  • Oracle-exact errors. Helpers emit AplError::Runtime("⍳: Argument …") with Kotlin-identical phrasing, not generic Rust errors.
  • Secure-mode aware. A flag in registration covers is_secure_gated without a separate match.
  • Testable in isolation. A native fn can be unit-tested with Engine::new() + helper constructors without spinning the full conformance harness.

Non-goals (for this cut)

  • Operators/adverbs (¨ ⍤ ⍣ ⍢ ˝) — they need function-operand plumbing. The trait is shaped for it (NativeOp), but the first landing ships functions only and leaves the adverbs in evaluator.rs.
  • Async / parallelism — engine is Rc-single-threaded today (Phase 7 ∥ is sequential). The trait uses Rc; a later Arc cut changes one alias.
  • Dynamic loading / plugins — registration is at Engine::new() time via `inventory` / explicit `register()` calls, not `dlopen`.
  • Breaking the 2987 — every existing oracle string stays byte-identical.

04 Proposed design — the trait

The core is a single object-safe trait. Everything else is helpers around it. One impl = one Kap name (qualified names like map:with are just a longer name).

// kap-core/src/native/mod.rs
pub trait NativeFn: fmt::Debug {
    /// Kap spelling as seen in source: "⍳", "+", "map:with", "my:mean"
    fn name(&self) -> &str;

    /// Namespace is part of `name` for now ("map:with" not ns="map" + "with"),
    /// so qualified lookup stays a single string compare. Split later if needed.
    fn arity(&self) -> Arity { Arity::Monadic }
    fn rank(&self) -> RankSpec { RankSpec::Any }
    fn secure_ok(&self) -> bool { true } // false = is_secure_gated
    fn doc(&self) -> &str { "" }

    /// The only required method. `args` is already forced (Deferred/Dynamic
    /// collapsed via `v.force(engine)`), and `ctx` carries the caller's Engine
    /// + Environment for the few fns that need it (`use`, `isLocallyBound`).
    fn call(
        &self,
        ctx: &NativeContext<'_>,
        args: Args,
    ) -> Result<AplRef<APLValue>, AplError>;
}

pub enum Arity { Monadic, Dyadic, Ambivalent }
pub enum RankSpec {
    Any,              // rank-polymorphic, fn handles its own rank (today's default)
    Scalar,           // rank-0 elementwise with full scalar-extension (Str as [len])
    Vector,           // rank-1 only, else "Rank mismatch"
    Fixed(usize),  // exact rank, for table ops
}

pub struct NativeContext<'a> {
    pub engine: &'a Engine,
    pub env: &'a AplRef<Environment>,
}
pub enum Args {
    Monad(AplRef<APLValue>),
    Dyad(AplRef<APLValue>, AplRef<APLValue>),
}
impl Args {
    pub fn mono(self) -> Result<AplRef<APLValue>, AplError>;
    pub fn dyad(self) -> Result<(AplRef<APLValue>, AplRef<APLValue>), AplError>;
}

Why object-safe + fmt::Debug

The registry is HashMap<String, Box<dyn NativeFn>>. Object-safety keeps it a single map; Debug makes engine.dump_natives() and panic messages useful. No associated types — Rank/Arity are data, not type parameters, so the dispatch stays a string lookup like today.

Why Args not two Options

Kap's valence errors are precise: “⍳ requires one argument” vs “+ requires two”. An enum makes the wrong-arity branch a single args.mono() / args.dyad() call that emits the oracle-exact text, instead of every impl re-matching Options.

Scalar helper — the 80% case

Most arithmetic builtins are “apply this element function with scalar-extension and rank-polymorphism”. That logic is factored into ScalarFn so +, ×, ⌈, | are each one closure:

05 Ergonomics — from 100 LOC to 12

Three layers: direct NativeFn for full control, ScalarFn for elementwise cases, and a proc-macro for the common “register and forget” path.

Before — eval_apply arm (~90 LOC)
After — NativeFn file (~12 LOC of logic)
"≢" => {
  let v = args.mono()?;
  // scalar? vector? Str is [len] ...
  // 30 lines of rank + empty-array edge cases
  // then the actual 2-line tally logic
}

…plus two more matches for is_primitive_name and is_known_fn, far from the logic. Tests live in tests/conformance.rs.

struct Tally;
impl NativeFn for Tally {
  fn name(&self) -> &str { "≢" }
  fn call(&self, _: &Ctx, a: Args) -> Result<_, _> {
    let v = a.mono()?;
    Ok(val(v.tally())) // KapArray dims, Str→[len], rank-0→1
  }
}

Co-located unit test with assert_kap!("≢ 3 4 ⍴ ⍳12", "3") — no harness needed.

Proc-macro sugar — the 30-second builtin

use kap_core::native::prelude::*;

/// Arithmetic mean — dyadic rank is scalar, monadic is "tally" sugar.
#[kap_fn(name = "my:mean", arity = "ambivalent", rank = "scalar")]
fn mean(a: Args) -> Result {
    match a {
        Args::Monad(v) => { // mean 1 2 3 → 2
            let n = v.tally()?; // helpers on AplRef<APLValue>
            let s = v.reduce_add()?;
            s.div(n)
        }
        Args::Dyad(w, v) => { // 2 mean 1 2 3 → weighted? demo
            w.as_number()?; // oracle error if not number
            todo_scalar("my:mean dyadic not yet")
        }
    }
}

Helper surface — Kap-flavored Rust
AplRef<APLValue> gains ergonomic extensions via KapExt: .as_number(), .as_char(), .elements(), .dims(), .is_scalar(), .scalar_extend(other), .tally(), val(n) / arr(dims, elems) constructors, and ctx.engine.new_array(...) for allocation. Error helpers bad_arg("⍳", "Argument must be rank 1") emit the Kotlin-identical prefix.

Scalar-arith example — the whole file

// kap-core/src/native/arith_add.rs — the "+" builtin, after migration
use super::{Args, NativeContext, NativeFn, Arity, RankSpec};
use crate::{APLValue, AplRef, AplError, KapNumber};

#[derive(Debug)] pub struct Add;
impl NativeFn for Add {
    fn name(&self) -> &str { "+" }
    fn arity(&self) -> Arity { Arity::Ambivalent }
    fn rank(&self) -> RankSpec { RankSpec::Scalar }
    fn call(&self, _: &NativeContext, args: Args) -> Result<AplRef<APLValue>, AplError> {
        super::scalar::apply_scalar(&AddImpl, args)
    }
}
struct AddImpl;
impl super::scalar::ScalarImpl for AddImpl {
    fn monad(&self, a: &APLValue) -> Result<APLValue, AplError> {
        match a { APLValue::Number(n) => Ok(APLValue::Number(n.clone())), // + is conjugate (no-op on reals)
                  _ => Err(AplError::runtime("_: unexpected type".into())) }
    }
    fn dyad(&self, a: &APLValue, b: &APLValue) -> Result<APLValue, AplError> {
        match (a, b) {
            (APLValue::Number(x), APLValue::Number(y)) => Ok(APLValue::Number(x.add(y))),
            (APLValue::Char(c), APLValue::Number(n)) => char_add(*c, n),
            _ => Err(AplError::runtime("+: type mismatch".into())),
        }
    }
}
// registration: inventory::submit! { NativeReg { factory: || Box::new(Add) } }

06 Registry & how the engine finds a name

Registration — explicit, no magic required

// Recommended: inventory crate (compile-time collection, no manual list)
inventory::submit! {
  NativeReg { name: "my:mean", factory: || Box::new(MyMean) }
}
// Engine::new() does:
for reg in inventory::iter::<NativeReg> {
    map.insert(reg.name.to_string(), (reg.factory)());
}
// Alternative (no inventory): Engine::register(Box::new(MyMean)) in lib.rs
// Both satisfy "one file = one builtin" — the second just needs one line
// in a central list, but still far from a 90-line match arm.

Deriving the gates

impl Engine {
  pub fn native_names(&self) -> Vec<String> {
    self.natives.keys().cloned().collect()
  }
  pub fn is_native(&self, name: &str) -> bool {
    self.natives.contains_key(name)
  }
}
// parser.rs: is_known_fn(name) = engine.is_native(name) || is_user_fn(name)
// evaluator.rs: is_primitive_name(name) = engine.is_native(name)
// is_secure_gated(name) = engine.natives[name].secure_ok() == false

The two-gate rule becomes one source of truth. Secure-mode filtering is a flag on the impl, not a second match.

07 Examples — the API in use

Example A · Pure monadic — ≢ tally (first axis, not flat count)

use kap_core::native::prelude::*;

#[derive(Debug)] struct Tally;
impl NativeFn for Tally {
    fn name(&self) -> &str { "≢" }
    fn call(&self, _: &NativeContext, args: Args) -> Result<AplRef<APLValue>, AplError> {
        let v = args.mono()?;
        // Str is [len] (rank-1), empty Str is rank-0 → tally 0, scalar → 1
        let n = if v.is_scalar_str() { 0 } else { v.dims().first().copied().unwrap_or(1) };
        ok_long(n as i64)
    }
}
inventory::submit! { NativeReg::of::Tally() }

Example B · Dyadic with scalar-extension — my:mean (weighted mean demo)

#[kap_fn(name = "my:mean", arity = "ambivalent")]
fn my_mean(ctx: &NativeContext, args: Args) -> Result {
    match args {
        Args::Monad(v) => {
            let elems = v.elements();
            if elems.is_empty() { return ok(APLValue::Null); }
            let sum = elems.iter().try_fold(KapNumber::Long(0), |acc, e| {
                let n = e.as_number().ok_or_else(|| bad_type("my:mean", "number"))?;
                Ok(acc.add(n))
            })?;
            let len = KapNumber::Long(elems.len() as i64);
            ok(APLValue::Number(sum.div(&len)?))
        }
        Args::Dyad(w, v) => {
            // dyadic path — scalar-extension handled by caller via RankSpec::Scalar
            // if we declared it, but we chose Any here to show manual handling:
            todo("weighted mean — left is weights")
        }
    }
}

Example C · Namespace builtin — map:with

#[derive(Debug)] struct MapWith;
impl NativeFn for MapWith {
    fn name(&self) -> &str { "map:with" }
    fn arity(&self) -> Arity { Arity::Dyadic }
    fn call(&self, _: &NativeContext, args: Args) -> Result<_, _> {
        let (keys, vals) = args.dyad()?;
        let k_elems = keys.elements(); let v_elems = vals.elements();
        if k_elems.len() != v_elems.len() {
            return Err(bad_arg("map:with", "keys and values must have same length"));
        }
        let map = KapMap::from_pairs(k_elems.into_iter().zip(v_elems))?;
        ok(APLValue::Map(map))
    }
}

Example D · Needs the environment — isLocallyBound

#[derive(Debug)] struct IsLocallyBound;
impl NativeFn for IsLocallyBound {
    fn name(&self) -> &str { "isLocallyBound" }
    fn call(&self, ctx: &NativeContext, args: Args) -> Result<_, _> {
        let sym = args.mono_as_symbol()?; // helper: expects a Symbol value
        let local = ctx.env.lexical_contains(&sym.name);
        ok_bool(local)
    }
}

08 Errors, rank & the oracle

Kap error messages are part of the contract — the conformance harness checks them indirectly via kind:"fails" rows, and users see them in the REPL. The native layer owns the phrasing.

Error helpers

pub fn bad_arg(name: &str, msg: &str) -> AplError {
    AplError::runtime(format("{}: {}", name, msg))
}
pub fn valence_err(name: &str) -> AplError {
    bad_arg(name, "requires two arguments")
}
// KapNumber helpers already emit "⍳: Argument must be …" etc.

Every helper prefixes with name: exactly as Kotlin does (IotaAPLFunction, TallyFunction). Tests assert the string.

Rank handling

RankSpecWhen to use
AnyYou handle rank yourself (e.g. ⍴, ⍉, ⌽ axis variants)
ScalarElementwise with scalar-extension — the framework broadcasts rank-0 vs rank-n before calling your element function
VectorRank-1 only, else Rank mismatch
Fixed(2)Matrix-only (e.g. a future ⌹ native)

Str is rank-1 [len] for rank purposes (empty Str is rank-0, matching dimensions()). The scalar helper respects this so "abc" + 1 → "bcd" works.

09 Testing a native in isolation

No need to regenerate kotlin_tests.jsonl to test one builtin. The harness helper assert_kap! spins a fresh Engine with the registry already populated (including your new entry via inventory).

// kap-core/src/native/my_mean.rs — co-located test
#[cfg(test)]
mod tests {
    use super::*;
    use kap_core::native::testutil::{assert_kap, assert_fails};

    #[test] fn mean_mono() {
        assert_kap("my:mean 1 2 3 4", "5/2");
        assert_kap("my:mean ⍳0", "⍬");
        assert_fails("my:mean @a", "my:mean: requires numbers");
    }
    #[test] fn mean_rank() {
        assert_kap("my:mean 2 2 ⍴ ⍳4", "(0.5 2.5)"); // per-row if Scalar rank
    }
}

Conformance still the gate
Unit tests are for fast feedback. The 2987-row run_kotlin_conformance sweep stays the release gate (cargo test --release -p kap-core). A new builtin should add a curated_kap_parity row if it has oracle-exact behaviour.

10 Migration — how we get there without breaking 2987

  1. New module, no behaviour change. Add kap-core/src/native/mod.rs with the trait + registry, and a compatibility shim: eval_apply first does if let Some(f) = self.natives.get(name) { return f.call(ctx, args) } then falls through to the existing match. Ship with one migrated builtin (e.g. ≢) to prove the path.
  2. Bulk move, file by file. Each existing arm is mechanically converted to a NativeFn impl in its own file. The old match arm becomes _ => unreachable!() once the registry covers it. Do ~10 per PR; each PR re-runs cargo test --release -p kap-core and the dump stays LC_ALL=C identical.
  3. Delete the match. When the map covers all ~120 names, remove the giant match and the hand-maintained is_primitive_name / is_known_fn lists — they become registry.keys() derivations. evaluator.rs drops from ~16 k to ~6 k LOC (dispatch + call-frame + return/throw plumbing).
  4. Operators next. Introduce NativeOp with fn apply(&self, ctx, left: Option<Box<Instr>>, right: Box<Instr>) for adverbs. Same registry, same gates.

What we deliberately keep in evaluator.rs

  • Call-frame creation (is_call_frame, is_return_target, dyn_active), → / throw / catch control flow, and Deferred/Dynamic forcing — these are engine plumbing, not per-builtin logic.
  • Train / strand / operator-combinator parsing — stays in parser.rs with derived is_known_fn.
  • Value model (APLValue, KapArray, KapNumber) — the API's vocabulary.

11 Extensions as crates — kap-ext-*

The same NativeFn trait that unblocks in-tree files is the public SDK for out-of-tree crates. A Kap extension is a normal Rust crate that depends on kap-core; linking it is registration — no dlopen, no unstable ABI, no second gate to drift.

What ships as a crate today

  • kap-core/src/native/sql_*.rs → kap-ext-sql
  • kap-core/src/native/arrow_*.rs → kap-ext-arrow
  • kap-core/src/native/jvm_*.rs → stays in core (needs Engine.secure_mode + libjvm gate) or splits to kap-ext-jvm when desired
  • Your code → kap-ext-my, kap-ext-stats, etc.

Splitting is a mv + Cargo.toml; the trait does not change.

Why not cdylib / dlopen

  • Rust has no stable ABI — Rc<APLValue> layout differs across rustc / RUSTFLAGS → SIGSEGV on AplRef in a .so.
  • Engine is single-threaded (Rc, RefCell) — a dynamic plugin cannot safely assume Send.
  • secureMode must statically omit io:/jvm: — dynamic loading breaks the hermetic gate.
  • Release tarball (main @ daedb3a) is hermetic — META-INF is already gitignored for this reason.

12 Open questions

QuestionOptionsLean
Inventory vs explicit list inventory (zero-maintenance, but a proc-macro dep) vs a hand-maintained vec![Box::new(Tally), …] in native/mod.rs inventory — ergonomic and already used in the ecosystem; fallback to explicit list is one line if we later dislike the dep.
Str as [len] The scalar helper must decide if Scalar rank treats Str as rank-1 (it is, per dimensions()). Alternative is a separate RankSpec::ScalarWithStr. Scalar = Str is rank-1 — matches current tail.rs semantics and makes "abc" + 1 just work. Keep the nuance in one place (scalar.rs).
Result vocabulary AplError::Runtime(String) today; richer AplError::Domain { name, msg, rank } would help tooling but diverges from Kotlin strings. Keep String — oracle strings are the contract; a structured error can be layered later.
Help / doc Should doc() feed )help in the REPL? Yes — doc() is already on the trait; wire it to help my:mean in a follow-up.
