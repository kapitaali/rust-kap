## [2026-08-16] PHASE 13 — user-defined functions (∇ tradfn, ⇐ short form, λ dfns) + test fix

**Two bugs fixed (cargo test was red):**

1. **`eval_lambda_apply` regression — `λ(a b)` was monadic.** All lambda construction
   sites hardcoded `split: 0`, so a 2-param `λ(a b) a+b` bound *both* `a` and `b` to the
   right argument (→ `3 g 4` gave `8` instead of `7`). Fix: the **last** param is the
   right arg (`⍵`); preceding params are left (`⍺`). `split = params.len().saturating_sub(1)`.
   Applied at all 4 sites: `Instr::Lambda` eval (evaluator.rs:162), `FnAssign` lambda branch
   (evaluator.rs:256), and the `eval_apply` lambda fast-path (evaluator.rs:351). Now
   `λ(a)`→monadic, `λ(a b)`→dyadic (a=left, b=right), matching Kap dfn conventions.

2. **OOM abort in `run_kotlin_conformance` — `1000000 1000000 ↑ 5 4 ⍴ ⍳20` aborted the
   whole `cargo test`.** `slice_axis` did `Vec::with_capacity(outer*target*stride)` =
   1e12 elements (8 TB) for a padded multi-axis take, and the `>100_000_000` guard ran
   *after* slicing (too late — the capacity request aborts via SIGABRT, which escapes
   `catch_unwind`). Fix: compute the final shape up front and reject runaway results
   *before* slicing (evaluator.rs:1243, in the `APLValue::Array` branch of take/drop).

## [2026-08-16] PHASE 13 (cont.) — recursion fixed; destructuring/block-apply root-caused

**Recursion bug FIXED (the deep-recursion returns-identity defect).** Deep recursion
(`fact 4`→`12`=4×3, `fib 10`→`17`=2×10−3) was wrong because the recursive call inside the
body was parsed as a *strand* `(fact N-1)`, not an apply — the parser didn't know `fact`
was a function until after the `∇` statement finished evaluating. Two changes:

1. Parser self-registers the function name **before** parsing the body
   (`parse_fn_def`, parser.rs:433-435; `parse_fn_assign`, parser.rs:398-400) so a recursive
   reference (`fact N-1`) inside the body parses as an application. `known_functions` is now
   a growable `Vec<String>` (was `&[&str]`) threaded through the parser (parser.rs:39-46,
   `is_known_fn`, `is_strand_operand` made `&self` methods).
2. `apply_user_fn` self-binds the function to its own name in the child scope
   (evaluator.rs:731-740) so names recurse by lookup in the call chain.

**Verified:** `fact 5`→`120`, `fact 10`→`3628800`, `fib 10`→`55`; shallow `fact 3`→`6`,
`g 3`→`3` still correct. 74 lib tests pass; `carated_kap_parity` gate green.

**Also added this session:**
- `◊` (U+25C8) accepted as `StatementSeparator` in lexer (Kap's real case separator; the
  kotlin_tests.jsonl `CustomFunctionTest` cases use it, not `⋄`). lexer.rs:148-149.
- `;` inside `( … )` groups parses as a vector literal `(10;20;30;40)` → array.
  parser.rs `parse_primary` group branch.
- Arg-count validation (arity) in `apply_user_fn` (evaluator.rs:702-715).
- Native-primitive redefinition guard + duplicate-arg detection in `parse_fn_def` /
  `parse_fn_assign`; `foo ⇐ 1` rejected (RHS must be a function).

**REMAINING — root-caused against real binary output, NOT yet fixed:**

1. **Argument destructuring broken.** Multi-name param groups must bind element-wise from a
   vector arg, with `⍺`/`⍵` = the whole left/right arg.
   - `∇ foo (x0;x1){x0+x1+1} ◊ foo (1;2)` → `(2 4)` (should be `4`): whole vector bound to
     first param, then `(1;2)+(1;2)+1`.
   - `∇ foo (A;B;C;D){A+B+C+D+1} ◊ foo (10;20;30;40)` → `(41 81 121 161)` (should be `101`).
   - Fix in `apply_user_fn` (evaluator.rs:716-725): when a param group has >1 name, bind each
     name to one element of the vector; single name → whole arg. Always set `⍺`/`⍵` to whole
     left/right value.

2. **`num2` index-out-of-bounds panic (hard crash).**
   `∇ foo (A;B){A+B+1} ◊ foo (10 ; foo (1;2))` → panic at evaluator.rs:783 `index out of
   bounds: len 1 but index 1` (array/array branch indexes `ye[i]` without per-cell length
   guard). Fix: skip/guard mismatched-length cells instead of indexing.

3. **Bare `{ … }` block applied as a function doesn't bind `⍵`/`⍺`.**
   `{ if(⍵≡0){10}else{1+⍓ 0} } 1` → `undefined symbol: ⍵`; `nestedDfns` / `nestedDnfsOuterRef`
   same. `eval_apply` (evaluator.rs:386-403) only handles `Lambda` + `Symbol→UserFn`; a bare
   `Instr::Block` fn_expr falls through. Fix: handle `Instr::Block` as monadic/dyadic fn
   (split 0, bind `⍵`/`⍺`, eval body in child scope) — same shape as the `FnAssign` Block
   wrapper at evaluator.rs:300-303.

4. **Dyadic-destructuring arity check counts elements, not args.**
   `∇ (x0;x1) foo (y0;y1){…} ◊ (10;11) foo (1;2)` → `expected 1 left and 1 right, got 1 left
   and 2 right`. The validator (evaluator.rs:703-709) uses `element_count`, but a left/right
   param *group* is one argument (a vector). Fix: arity = number of *arg slots* (left group +
   right group = 2), not element count.
