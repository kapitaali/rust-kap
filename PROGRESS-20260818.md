# Progress — 2026-08-18

## [2026-08-18] Strings: `unicode:*` builtins added + merged to main

Implemented the 8 `unicode:` namespace builtins in the Rust Kap interpreter,
mirroring `~/Apps/array/array` (Real Kap / Kotlin) `unicode.kt`:

- `unicode:toCodepoints`  — char / string → codepoint vector
- `unicode:fromCodepoints` — codepoint vector → string (errors on non-integer
  / out-of-range, per Kotlin)
- `unicode:toGraphemes` — string → vector of one-element strings (uses
  `unicode-segmentation`)
- `unicode:toLower` / `unicode:toUpper` — case conversion (Unicode-aware)
- `unicode:toNames` — Unicode name of a char, or `⍬` when unnamed
- `unicode:enc` — string → byte-number vector in a charset (`"UTF8"` default;
  `"UTF16"`, `"UTF16LE"`, `"UTF16BE"`, `"UTF32"` supported). Charset is a
  **left argument string** (e.g. `"UTF16" unicode:enc "A"`).
- `unicode:dec` — byte-number vector → string in a charset (left-arg, default
  UTF8).

### Parser fix (critical)
The lexer splits `unicode:enc` into `Symbol{name:"enc", namespace:Some("unicode")}`,
so a bare-name lookup fails and the dyadic form strands. Fixed by threading the
namespace through `is_known_fn(name, namespace)` and reconstructing the qualified
`ns:name`. `is_primitive_op` stays BARE-names-only so namespaced builtins are not
forced monadic (which would drop the left operand). This is the same wiring pattern
as `io:print`.
