## [2026-08-18] Strings: `unicode:*` builtins added + merged to main

Implemented the 8 `unicode:` namespace builtins in the Rust Kap interpreter,
mirroring `~/Apps/array/array` (Real Kap / Kotlin) `unicode.kt`:

- `unicode:toCodepoints`  — char / string → codepoint vector
- `unicode:fromCodepoints` — codepoint vector → string (errors on non-integer
  / out-of-range, per Kotlin)
- `unicode:toGraphemes` — string → vector of one-element strings (uses
  `unicode-segmentation`)
- `unicode:toLower` / `unicode:toUpper` — case conversion (Unicode-aware)
- `unicode:toNames` — Unicode name of a char, or `⍬` when unnamed
- `unicode:enc` — string → byte-number vector in a charset (`"UTF8"` default;
  `"UTF16"`, `"UTF16LE"`, `"UTF16BE"`, `"UTF32"` supported). Charset is a
  **left argument string** (e.g. `"UTF16" unicode:enc "A"`).
- `unicode:dec` — byte-number vector → string in a charset (left-arg, default
  UTF8).

### Parser fix (critical)
The lexer splits `unicode:enc` into `Symbol{name:"enc", namespace:Some("unicode")}`,
so a bare-name lookup fails and the dyadic form strands. Fixed by threading the
namespace through `is_known_fn(name, namespace)` and reconstructing the qualified
`ns:name`. `is_primitive_op` stays BARE-names-only so namespaced builtins are not
forced monadic (which would drop the left operand). This is the same wiring pattern
as `io:print`.

### Files
- `kap-core/Cargo.toml` — added `unicode-segmentation = "1"`
- `kap-core/src/evaluator.rs` — 8 dispatch arms in `eval_apply` + helpers

  `unicode_case`, `unicode_to_names`, `unicode_enc`, `unicode_dec`), `Charset`
  enum + `unicode_encode`/`unicode_decode`/`unicode_char_name` free fns.
- `kap-core/src/parser.rs` — `is_known_fn(&self, name, namespace)`; all symbol
  call sites pass `namespace`.

## [2026-08-18] Strings-phase: strings as proper rank-1 arrays + `curated_kap_parity` gate

### Problem
`APLValue::Str` carried no array shape, so structural primitives that treat a
string as a vector of chars failed or were wrong vs Real Kap:
- `⍴"abc"` → `""` (Real Kap: `(3)`); `⍴⍴"abc"` → `(0)` (Real Kap: `(1)`)
- `⌽"abc"`, `⍉"abc"` → "not implemented for this value type"
- `⍪` → "undefined symbol" (parser didn't know it)
- `"abc"⍴⍳100` → "reshape dimensions must be an array or integer"
- `⊃"abcdef"` returned the whole string; `"abcdef"[2]` errored ("pick into rank-0")

### Fix (faithful to Kotlin `APLBmpString.dimensions = dimensionsOfSize(len)`)
- `kap-core/src/lib.rs` — added `APLValue` accessors `dimensions()`, `rank()`,
  `element_count()`, `value_at(i)` that treat `Str` as a rank-1 vector of its
  chars (scalars are rank 0). No restructuring of the 33 `Str(...)` sites.
- `evaluator.rs`:
  - `shape` now returns `[len]` for a `Str`.
  - `tally` returns char count for a `Str` (`≢"abc" → 3`).
  - `reverse_axis` (⌽/⊖) gained a `Str` arm: reverses/rotates the chars,
    returns a `Str` (`⌽"abc" → "cba"`, `1⌽"abc" → "bca"`).
  - `transpose` (⍉) returns the `Str` unchanged (rank-1 identity).
  - `catenate` (`,`/`⍪`): two strings concatenate into a `Str`
    (`"foo","bar" → "foobar"`); `⍪` added to `is_primitive_op` in parser.rs.
  - `reshape` accepts a `Str` left arg as `(len)` (`"abc"⍴⍳100 ≡ (3)⍴⍳100`).
  - `first` (⊃) returns the first char of a string (`⊃"abcdef" → @a`).
  - `pick` treats a `Str` as a rank-1 char vector, so bracket indexing returns
    char scalars (`"abcdef"[2] → @c`, `"abcdef"[0 2] → "ac"`).
- `lib.rs` `format_display`: fixed empty-array bug — an empty array vacuously
  matched "all char" and rendered as `""`; now requires non-empty, so `⍳0`
  renders `()`.

### `curated_kap_parity` gate now runs to completion (was aborting on the
`run_kotlin_conformance` panic) and is GREEN.
- Switched the curated renderer to `format_display` (REPL form: strings quoted,

- Added ~40 verified String/Char/Unicode curated cases (⍴/⍴⍴/≢/⌽/⍉/⊃/pick,
  character arithmetic, `⍕`/`⍎`, and the 8 `unicode:*` builtins), each confirmed
