### Root causes (all diagnosed against Kotlin source, not memory)

1. Nested targets: `DestructAssign { names: flat Vec }` accepted only flat
   `Array[Symbol…]`; `((a b) c)` fell to `Assign{target: Array}` → eval
   `assignment target must be a symbol`. `;`-nested `(a;(b;c);d)` never reached
   `←` as one target — `ListSeparator` split the accumulator → `Can only assign
   to a single variable`.
2. `;`-lists did not exist in the Kotlin accumulator at all: baseline port
   errored `unexpected token in primary` on ANY `;` outside `⟦⟧`/legacy paths
   (`1+2;3+4`, `1;2;3` all UNSUPPORTED at baseline).
3. `b ((b←2) + 10)` parses as `Array[b, Apply{+, Assign}]`; port evals array
   elements left-to-right so the `b` lookup runs before `(b←2)`. Kotlin
   `Literal1DArray.eval` runs right-to-left (`downTo 0`). Separate risky
   change — deliberately NOT touched here; stays UNSUPPORTED.

### Fix (uncommitted: `ast.rs`, `evaluator.rs`, `parser.rs`)

- `ast.rs`: `DestructAssign { names, semicolon }` → `{ target: Box<Instr>,
  value }`. Target mirrors LHS shape to any depth (`Array` = space group,
  `List` = `;` group, `Symbol` leaves).
- `parser.rs` `parse_value_kotlin_with`: new `lists` accumulator — `;` builds
  `Instr::List` (Kotlin `parseListInner`, parser.kt:335-364), incl. function-
  element rejection with both oracle texts (`can't` first / `cannot` later),
  `is_list_element_fn` (bare value Symbols NOT fn-shaped — needs primitive /
  known-fn / `⇐`-bound test), error propagation through the paren-group arm,
  and a `;`-after-function guard in `finish_fn_call` (`+ ; 3 ; 4 ; 5` /
  `1 ; + ; 2` now parse-error like the oracle instead of applying `+`).
- `parser.rs` `LeftArrow` arm: `(a) ← v` → plain `Assign` (whole-RHS bind);
  any valid target tree (`is_destruct_target`) → `DestructAssign{target}`;
  non-symbol leaf → plain `Assign` → eval error (oracle `Unable to assign to
  expression`, 1:4 position differs — harness never asserts text).
- Legacy `parse_assign` flat path rebuilt on the new shape (symbols only).
- `evaluator.rs`: `bind_destruct_target` (recursive `deriveLvalueReader`,
  instr.kt:82-101/276-291; `Array`↔rank-1+len, `List`↔list+size, const check
  per leaf), RHS `collapse()` (instr.kt:518-524); const-sim recurses per leaf
  (`check_target_const`). Fixed pre-existing `{:?}}}` typo in rank-1 error.
- FAILED EXPERIMENT (reverted same session, do NOT retry): extending the
  paren-group `finish_fn_call` guard to keep `Array`/`List` targets out of
  `processFn` fixed `((a b) c)` in isolation but broke curated
  `(10 (×foo-) 20)` → 0 (expected 1) + `10 (×foo 20) 30` → `unknown
