## [2026-08-22] ⊥/⊤ are BASE-VALUE functions, not byte codecs (io.kap base64 blocker)

### Root cause (corrected — prior PROGRESS-20260821 was misled)
The port aliased the APL glyphs to the **byte-array codec** builtins:
```rust
// evaluator.rs ~line 1488
"⊤" | "encode" => self.encode(left_val, right_val),
"⊥" | "decode" => self.decode(left_val, right_val),
```
That is WRONG. `encode`/`decode` (ASCII names) ARE byte codecs, but `⊤` and `⊥` are the
**mixed-radix base-value** functions, defined entirely in the stdlib `math-kap.kap`
(`~/Apps/array/array/standard-lib/math-kap.kap` lines 64-103; vendored at
`kap-stdlib/std/math-kap.kap`). The Kotlin engine has NO native `⊤`/`⊥` — the oracle's
behavior IS `math-kap.kap`.

The aliasing produced `256 ⊥ 104 105 0 → 104` (naïve scalar-base zip) instead of the
oracle's `⟨6842624⟩`.

### Authoritative oracle definitions (math-kap.kap, verbatim)
```
∇ (A) ⊥ (B) {                       ∇ (A) scalarEncode (B) {
  1≥≢⍴A or 'kap:InvalidDimensions…'    B≥0 or '…B must be positive'
  +⌿ (×⍀ ¯1↓1⍪(0×B) (+⍤¯1) ⌽A) × ⊖B   res←(0,⍴B)⍴B
}                                    while(∨/,0≠B){ div←⌊B÷A
∇ (A) vectorEncode (B) {               rem←B-div×A  res←rem⍪res  B←div }
  res←(0,⍴B)⍴B                        }
  while(0≠≢A){ div←⌊B÷↑A           }     ∇ (A) ⊤ (B) {
    rem←B-div×↑A  res←rem⍪res            if(⍬≡⍴A){ A scalarEncode B }
    A←↓A  B←div }                       } else { (⌽A) vectorEncode B }
}                                    }
```

### Fix chosen (approach 1 from base_value_encode_decode.md ref)
Reimplement the port's native `decode`/`encode` as the **base-value** algorithm, and
**remove the `| "encode"` / `| "decode"` alias** so the byte-codec keeps its own ASCII
names (`encode`/`decode`) and `⊤`/`⊥` are purely base-value. The stdlib `math-kap.kap`
is already loaded (via `math.kap → use("math-kap.kap")`), so the real definitions will
also be present and will agree with the native impl.

The general `⊥` (decode) = `+⌿ (×⍀ M) × ⊖B` where `M = ¯1↓ (1⍪ ((0×B) (+⍤¯1) ⌽A))`:
- `⌽A` reverses the radix vector A.
- `(+⍤¯1)` broadcasts/laminates that reversed radix into each *cell* of the trailing
  axis of `B` (the digit matrix): result shape `(⍴B)` with the radix prepended along
  axis 0 → `(1+⍴B[0]) , ⍴B[1..]`.
- `1⍪` prepends a row of 1s; `¯1↓` drops the last of axis 0 → same shape as `B` but
  with the *first* leading-cell column = 1 (the most-significant weight).
- `×⍀` = scan-product along axis 0 (column-wise cumulative product from the top).
- `⊖B` reverses the trailing (last) axis of B (least-significant digit first).
- `+⌿` = sum along axis 0.

The scalar-radix sub-case (`A` is a scalar, e.g. `2 ⊥ 1 2 3`) reduces to standard
`Σ d_i * 2^(n-1-i)` per trailing-axis vector, BUT the matrix case confirms the general
form is a full (scan-product) weighting, not per-row independent powers — proven by
`2 ⊥ 3 3⍴1 2 3 4 5 6 → ⟨13 20 27⟩` (not `⟨11 11 11⟩`).
