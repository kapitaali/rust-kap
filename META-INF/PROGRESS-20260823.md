## [2026-08-23] Tier A CLOSED — operator-derivation parse + keyword-symbol fix (⌸/⎕A/⎕p/when all oracle-parity)

Two parser blockers remained between the native `⌸` (landed 2026-08-22) and real Tier A
acceptance via `use("base-functions.kap")` (the stdlib `⌸` def, NOT the native builtin). Both
fixed; every acceptance symbol probed side-by-side against the oracle.

### Blocker 1 — `(≠⌸)` failed to PARSE as an operator-derivation when `⌸` is a known user-op
`base-functions.kap` defines `∇ (keys) (fn ⌸) (values) {…}` so inside the file `⌸` becomes a
**known user-operator** (`known_ops.contains("⌸")`). The port's `try_parse_train` classified
`(≠⌸)` as a "symbol-list literal" and returned `None`, so the surrounding call site threw
`expected a function in train`.

**Root cause (two sub-bugs):**
- The operator-derivation block I added earlier built `Instr::OpCall` when `⌸` is a known op,
  but `is_function_expr` (and `is_definite_function`) did NOT include `OpCall`. So the
  1-member-train wrap (`funcs.len()==1 && is_function_expr(...)`) failed → `try_parse_train`
  returned `None` → parse error.
- A **keyword symbol** (namespace `== "keyword"`, e.g. `:export`) was wrongly allowed to bind
  as the *left operand* of an operator-derived member: `declare(:export ⌸)` parsed as
  `Derived{:export, ⌸}` → eval error `unknown function: keyword:export`. In Kap, `:export` is a
  declaration *value* that strands into the array `[keyword:export, ⌸]` (Kotlin treats
  `declare(:export a)` as `[Symbol{export,keyword}, Symbol{a}]`).

**Fixes (parser.rs):**
1. `is_function_expr` now matches `Instr::OpCall { .. }` (so a single `(≠⌸)` / `(f g⌸)` wraps as
   a 1-member train and applies to the surrounding `k … v`).
2. `is_definite_function` now matches `Instr::OpCall { .. }` (so 2-train chaining with a
   user-op-derived member works too).
3. The operator-derivation block bails (`funcs.push(e)` instead of binding) when the preceding
   member `e` is a keyword symbol (`matches!(e, Instr::Symbol{namespace:Some(ref ns),..} if ns=="keyword")`),
   so `:export ⌸` → `[keyword:export, ⌸]` array, never a Derived.

### Blocker 2 — `use("base-functions.kap")` now loads clean
With the keyword-symbol fix, `declare(:const (⎕A ⎕a ⎕d))` and `declare(:export ⌸)` both parse
and the file loads. `⌸` (stdlib def) is registered via `declare(:export ⌸)`.
