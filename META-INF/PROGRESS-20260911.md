## ∇/⇐ shadowing fix — ROOT CAUSE FOUND & FIXED

**Bug:** `∇` tradfn overwrote `⇐` binding in the port; oracle keeps them separate.

### Oracle behavior (kap-jvm-text, stdin)

```
foo ⇐ { ⍵+10 }
foo 100        → 110
∇ foo (x) { x+20 }
foo 160        → 170  (⇐ binding, NOT ∇)
```

Second probe (⇐ after ∇):
```
∇ foo (x) { x+1 }
foo 5          → 6
foo ⇐ { ⍵+100 }
foo 5          → 105  (⇐ binding shadows ∇)
```

### Root cause

In Real Kap, `∇` tradfns register in an **engine-global** function table
(`engine.functions`, `parser.kt:671-678 registerDefinedUserFunction`), while
`⇐` creates a **local/module** variable (`UpdateLocalFunctionInstruction`,
`parser.kt:579-599`). Local variables shadow engine-global functions.

The port wrote both to the same namespace table (`env.define()`), so `∇`
overwrote `⇐`.

### Fix (2 files, +33/-3)

**`kap-core/src/lib.rs` — `Environment::engine_fns` field:**
- New `Rc<RefCell<HashMap<String, AplRef<APLValue>>>>` field — the engine-global
  function table, shared across all scopes via `Rc` clone.
- `child()` clones from parent so all scopes see the same table.

**`kap-core/src/evaluator.rs`:**
- `UserFnDef` arm (∇): write to `env.engine_fns` instead of `env.define()`.
- `lookup()`: added a final step — check `engine_fns` AFTER lexical scope,
  namespace table, and home-ns anchor. This ensures `⇐` bindings (namespace
  table) shadow `∇` bindings (engine_fns), matching Kotlin's lookup order.
