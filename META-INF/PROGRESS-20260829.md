## [2026-08-29] `⟦⟧` function-call bracket semantics (P1-M15, resume)

**Branch:** `feature/wheres-extra` @ `79485b1` (uncommitted WIP below).
**Gates before this work:** lib 96/0 · curated 1/0 (both GREEN).

### What was already broken (root cause located)
`⟦⟧` (Kotlin `FunctionCallOpenParen`, parser.kt:440) was only HALF-wired. Commit
`f3c1920` had changed `parse_function_call_list` to emit `Instr::List`, but commit
`0ad8c36` (the `∇ returns Null` fix, intended to touch ONLY evaluator.rs) accidentally
reverted that one line back to `Instr::Array`. Net effect: `⟦⟧` contents returned as a
stranded array and the function was never applied monadically.

### Oracle ground truth (captured, not predicted)
```
+/⟦1 2 3 4⟧        → ⊢ 10                      (space ⇒ STRAND/array, reduce → 10)
+/⟦1;2;3;4⟧        → ⊢ ╔═╤═╤═╤═╗              (semicolon ⇒ LIST; reduce of a LIST returns it)
{⍵}⟦1 2 3 4⟧       → ⊢ ⟨1 2 3 4⟩              (space ⇒ arg is the strand array)
{⍵}⟦1;2;3⟧         → ⊢ ╔═╤═╤═╗                (semicolon ⇒ arg is a LIST)
g⇐{⍵} ⋄ g⟦⟧        → ⊢ ╔⊖╗                    (empty ⇒ empty LIST)
⍴⟦1;2;3;4⟧         → ⊢ ⍬                       (LIST is RANK-0!)
typeof ⟦1;2;3;4⟧   → ⊢ kap:list
≢⟦1;2;3;4⟧         → ⊢ 1                       (tally of a rank-0 scalar is 1)
+/5                → ⊢ 5                       (reduce of a rank-0 scalar returns it — NO error)
```

### Three coordinated fixes (all required for correct `⟦⟧` semantics)

1. **`parse_function_call_list` (parser.rs:~1067) — three-way dispatch on contents.**
   Kotlin `parseExprToplevel(FunctionCallCloseParen)` → `parseListInner` decides:
   empty ⇒ `APLList(emptyList)`; `;`-separated ⇒ `LiteralAPLList` (a LIST); space-stranded
   (no `;`) ⇒ the single stranded expression DIRECTLY as the argument (NOT wrapped in a
   list). Port changed accordingly: added `saw_semicolon` flag; empty returns
   `Instr::List{[]}`; `;` returns `Instr::List{elems}`; space returns the single stranded
   expression as `right` directly.

2. **`Instr::List` eval arm (evaluator.rs:708) + `dimensions()`/`rank()` (lib.rs) — rank-0
   SEMANTICS via accessor override.** A Kap List is `APLList : APLSingleValue`
   (types.kt:1024) with `dimensions = emptyDimensions()`, i.e. rank 0. So a List reports
   shape `⍬`, tally `≢` 1, and `+/` of a list returns the list. Implementation (Approach B —
   chosen after Approach A regressed `regex:replace`): storage STAYS rank-1
   (`KapArray::new(vec![vals.len()], …)`) so `element_count()`/`elements()` keep their
   KapArray invariants, while `APLValue::dimensions()` (`List(_) => vec![]`) and
   `APLValue::rank()` (`List(_) => 0`) in lib.rs special-case List to rank 0. This is the
   same accessor-override pattern `Str` already uses. (Approach A — storing the List with
   EMPTY dims `vec![]` — made `element_count()` return 1 instead of N and broke
   `regex:replace`, whose `(subject;replacement)` pair test does `element_count() == 2`.)

3. **`adverb_reduce` rank-0 (evaluator.rs:7960) — return the value, don't error.** Kotlin
   `ReduceAPLFunctionImpl.eval1Arg` (reduce.kt:282-286): `if (aDimensions.size == 0) return a`.
   The port errored "reduce: cannot reduce a scalar" — wrong for BOTH `+/5` (oracle `5`) and
   `+/⟦1;2;3;4⟧` (oracle boxed list). Changed the `rank == 0` arm to `return Ok(data)` with an
   explicit non-0 axis still erroring per Kotlin `IllegalAxisException` ("Axis N is not
   valid. Expected: 0").

### Status: COMPLETE — all three fixes landed; both gates GREEN

### Verified (port value → oracle)
```
+/⟦1 2 3 4⟧   → 10            ✅ (= oracle 10)
+/⟦1;2;3;4⟧   → ⟨1 2 3 4⟩     ✅ (list, not reduced; oracle boxed ╔═╤═╤═╗ — display divergence)
{⍵}⟦1 2 3 4⟧  → (1 2 3 4)     ✅ (strand array; oracle ⟨1 2 3 4⟩ — display divergence)
g⟦1;2;3⟧     → ⟨1 2 3⟩       ✅ (list; oracle boxed — display divergence)
g⟦⟧          → ⟨⟩            ✅ (empty list; oracle ╔⊖╗ — display divergence)
⍴⟦1;2;3;4⟧   → ()            ✅ (rank-0, shape ⍬; oracle ⍬ — display divergence)
typeof ⟦1;2;3;4⟧ → kap:list  ✅ exact
≢⟦1;2;3;4⟧   → 1             ✅ exact
+/5          → 5             ✅ exact
(a;b;c)←(1;2;3) ⋄ c → 3      ✅ (destructuring still works — no regression)
```

All value semantics match; the residual `⟨⟩`/`()` vs box-frame differences are the known
P8 DISPLAY divergence (documented in KNOWN-NONCONFORMANCE.md §"`⟦⟧` boxed-list DISPLAY

## [2026-08-29] `⟦⟧` call-bracket CONTINUATION — dyadic operator after a closed call

**Branch:** `feature/wheres-extra` (uncommitted follow-up to the `⟦⟧` semantics work).

### Symptom (conformance regression)
`functionCallWithOperatorAndOuterFunctionCall0`: `+/⟦1 2 3 4⟧ + 100` →
oracle `110`, port `100`. The `⟦⟧` result (`10`) was being DROPPED as a left operand.

### Root cause
Kotlin `processFn` (parser.kt:440-449) returns the `⟦…⟧` call as an **InstrParseResult**
(a VALUE), which the outer `parseExpr` loop pushes into `leftArgs` and CONTINUES — so a
following dyadic operator (`+ 100`) binds to it (`(10)+100 → 110`). The port's
`finish_fn_call` `⟦` branch returned the `Apply` TERMINALLY, so `parse_value_kotlin`
ended the statement and the trailing `+ 100` was re-parsed as a separate monadic `+` (`→ 100`).

### Fix (parser.rs)
1. Split `parse_value_kotlin` into a thin wrapper + `parse_value_kotlin_with(seeded:
   Vec<Instr>)` that resumes the accumulator loop with a pre-seeded `left_args`.
2. `finish_fn_call`'s `⟦` branch now does `left_args.push(call)` then
   `return self.parse_value_kotlin_with(std::mem::take(left_args))` — the closed call's
   VALUE continues accumulating as a left operand (exactly Kotlin's parseExpr model).

### Verified (port → oracle)
```
+/⟦1 2 3 4⟧ + 100   → 110   ✅ (= oracle; was 100)
+/⟦1 2 3 4⟧ × 2     → 20    ✅
sum⇐+/ ⋄ sum⟦1 2 3 4⟧ → 10 ✅ (idiomatic named-function form)
```
`2 + +/⟦…⟧` (operator-composed, NON-idiomatic Kap) deliberately left unfixed — `⟦⟧`
only ever follows a named function in real Kap code.

## [2026-08-29] Membership, catenate-empty, Null round-trip — three focused divergences

**Branch:** `feature/wheres-extra` (uncommitted).

### 1. `∊` membership — VALUE equality, not format-string keys (evaluator.rs:10096)
`compareDoubleInteger0/1`: `3.0 ∊ 2 3` → oracle `1`, port `0`. `membership` keyed the
right-arg set by `format_value()` strings; `3.0` formats as `"3.0"` and `3` as `"3"`, so
a Double never matched a Long. Fixed: compare with `Self::deep_equal` (numeric value
equality, same as `=`/`≠`; NOT the type-strict `≡`/`≢` key). Also now admits `List` right
args. Verified: `3.0∊2 3`→`1`, `3∊2 3.0`→`1`, `5∊2 3`→`0`, `1 2∊2 3 4`→`(0 1)` — all oracle-exact.

### 2. Dyadic `,` catenate absorbs a whole empty array (evaluator.rs:5062)
`concatenateReduce1D*`: `,/1 2 3 ⍬ 4` → oracle `(1 2 3 4)`, port `(1 2 3 "" 4)`.
Kotlin `joinByAxis` (concatenate-array.kt:203-211): a whole empty/`⍬` operand (dims `[0]`)
returns its partner. Added `if a.is_null() → b` / `if b.is_null() → a` before the string
fast-path. A `⍬` that is an ELEMENT of a strand (`1 2 3 , ⍬ 4` → `(1 2 3 ⍬ 4)`) still
preserved (it arrives inside a strand's array, not as a bare Null).

### 3. `apl_to_instr` Null round-trip (evaluator.rs:7890)
Root cause of the `""` above: `apl_to_instr` mapped `APLValue::Null → Str("")`, so a `⍬`
element in a `,/` reduce was re-applied as an empty STRING (invisible to the Null guard).
Changed to `Null → Instr::Empty` (which evals back to `APLValue::Null`). This is the
general fix; the reduce path (`apply_fn_instr`) now carries Null faithfully.
