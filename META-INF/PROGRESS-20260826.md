## [2026-08-26] OPEN-4 — `throw` native function (CLOSED)

### Resume
PROBLEM.md lists OPEN-4 `throw` as genuinely open: port gave `error: undefined symbol: throw`.
Oracle ground truth (Kotlin `ThrowFunction`, engine.kt:411, div_functions.kt:254-267):
- **Monadic** `throw x` ⇒ `TagCatch(key=error-symbol, data=x)`.
- **Dyadic** `a throw b` ⇒ `TagCatch(key=a, data=b)`.
- `TagCatch` message = `description ?: tag.data.formatted(PLAIN)`; REPL renders any
  TagCatch as `<fn-name>: <data>`, so the tag **key is NOT shown** in the message body.

### Empirical oracle probes (message body only; `Error at: L:C:` position prefix is the
port's global error-format convention, not throw-specific — see P8 gap)
```text
throw "x"        O> Error at: 1:1: throw: x        R> error: throw: x
throw 5          O> Error at: 1:1: throw: 5        R> error: throw: 5
99 throw "msg"   O> Error at: 1:4: throw: msg      R> error: throw: msg
throw "long string…"  O> Error at: 1:1: throw: classify is only valid for vectors of length 1
                      R> error: throw: classify is only valid for vectors of length 1
```
The **message body is oracle-exact** (`throw: <data>`, PLAIN rendering so strings
drop quotes). Only the leading `Error at: 1:1: ` positional prefix differs — that is
the port's existing top-level error formatter (pre-existing gap, applies to ALL errors,
not throw-specific); left as a separate P8-flavored issue rather than expanding scope here.
