## Active Investigation: `defsyntaxsub` Body Parsing Bug

### Symptom

After `use("structure.kap")`, the `when` macro fails with:
```
In destructuring assignment, expected a rank-1 array of 2, got dimensions: []
```

This blocks `io:encodeUtf8`, `io:toHex`, `io:fromHex`, `o3:format`, and any
code path that uses `when`.

### Root Cause Analysis — PARTIALLY SOLVED

#### Parser Side — FIXED TODAY

`defsyntaxsub whenInner` has body `cond thenStatement` — a strand of two
symbols that should parse as a single 2-element array expression. But the
parser's `parse_block()` (used by `parse_defsyntax_directive()` for the
`is_sub` branch) treats each newline-separated item as a separate statement,
splitting the strand into two statements instead of one expression.

**Fix applied in `parse_defsyntax_directive()`** (line 7168-7184):
```rust
let body = if is_sub {
    self.skip_newlines();
    self.kotlin_close_stack.push(Token::CloseBrace);
    let result = self.parse_value_kotlin();
    self.kotlin_close_stack.pop();
    self.skip_newlines();
    if matches!(self.peek(), Some(t) if matches!(t.token, Token::CloseBrace)) {
        self.advance();
    }
    result?
} else {
    self.parse_block()?
};
```

**Verified with eprintln debug output**: the body now parses correctly as
`Array { elements: [Symbol { name: "cond" }, Symbol { name: "thenStatement" }] }`.

#### Runtime Side — STILL BROKEN

The error occurs at runtime when destructuring `↑entryList[i]` into
`(cond fn)`. The `:repeat (entryList whenInner)` rule collects entries from
`expand_sub_macro`, but the destructuring expects a rank-1 array of 2 and
gets an empty array `[]`.

**Debug output shows** `expand_sub_macro` IS being called repeatedly with
the correct rules: `[NExprFunction { var: "cond" }, NFunction { var: "thenStatement" }, Optional { inner: [Special { token: Newline }] }]`.

**Key observation**: The error is `dimensions: []` which is what
`APLValue::dimensions()` returns for a NonBoundFn (line 724 in lib.rs:
`_ => vec![]`). This means the destructuring target is receiving a
NonBoundFn value instead of the expected 2-element array.

**Possible cause**: The `expand_sub_macro` binds `cond` and `thenStatement`
as `NonBoundFn` values (because they're `:nexprfunction` and `:nfunction`).
When the sub-macro returns a `MacroExpand` with these bindings, the
`MacroExpand` evaluation at line 1614-1656 evaluates the body `(cond thenStatement)`
in a child environment. But the body is `Array { elements: [cond, thenStatement] }`
which evaluates to an array of NonBoundFn values. The `↑entryList[i]` take
from this array should give a 2-element array, but if `entryList` itself is
empty or the entries are malformed, the destructuring fails.

## Session 2026-09-12 (continued) — `when` RUNTIME root cause FOUND & FIXED

**Verdict on prior analysis:** the macro chain was never broken. `defsyntaxsub`
body parsing (parser fix), `:repeat` collection (`MultiResultInstr` shape),
`MacroExpand`/`CallWithVarInstruction` eval all match Kotlin. The bug was in
bracket indexing (`index_select`, evaluator.rs:15319).

**Root cause:** `(cond fn) ← ↑entryList[i]` needs `↑entryList[i]` to be a
2-array. Port's `a[0]` on a nested array DISCLOSED the element (returned the
bare 2-array), so `↑` took its first element (a scalar NonBoundFn) and the
2-destructure failed with `dimensions: []`. Oracle probe:
`a ← (⊂10 20),(⊂30 40) ⋄ a[0]` → enclosed box holding `(10 20)`;
`↑a[0]` → `(10 20)`; `(p q) ← ↑a[0]` works.

**Kotlin anchors (read before coding, all verified in source):**
- `lookup.kt:159-161` — `PickResultValue.unwrapDeferredValue` →
  `unwrapEnclosedSingleValue(this)`.
- `reduce.kt:181-187` — scalar-shaped pick result wraps the picked element via
  `EnclosedAPLValue.make`.
- `types.kt:1554-1560` — `make`: `APLSingleValue` (Number, Char, Symbol, Map,
  List, Nil, LambdaValue; `APLNumber` per number.kt:8) discloses, everything
  else (arrays incl. `APLString`, `⍬`) encloses in a rank-0 box.

**Fix (evaluator.rs `index_select`, scalar-result arm):** force the element,
passthrough for Number/Char/Symbol/Map/List/Nil/UserFn/UserOp/Escape/

`↑`/destructure edits.

### Design decision — call-by-name thunk, not listener invalidation

Kotlin's `DynamicAssignmentInstruction` registers change listeners on the RHS's source
symbols and re-evaluates when they change. The port is single-threaded with no
mutation-listener bus, so the same OBSERVABLE behaviour is obtained with a
call-by-name THUNK in the variable slot: `APLValue::Dynamic { instr, env, id }`. The
thunk re-evaluates on EVERY read (`force()`), so a later change to any dependency is
visible. A plain `←` overwrites the slot and thereby DROPS reactivity — which mirrors
Kotlin's `processDestinationUpdated` unregistration. Cycles are caught by an id guard
and raise an error instead of recursing. No `MPLock` is needed single-threaded.

### Fix 1 — namespaced `∇` tradfns were invisible to the parser (`simpleInclude`)

A `∇` tradfn registers ONLY in `Engine.engine_fns` (Kotlin `engine.registerFunction` →
`engine.functions`) and never in the namespace `symbols` table, so
`NamespaceRegistry::collect_function_names` — which requires `symbols[ns][name]` to be a
`UserFn` — skipped it, and the qualified `foo:a` never reached `known_functions`.
Kotlin resolves `foo:a 100` via `lookupFunction` → `engine.getFunction(foo:a)`, keyed by the
NAMESPACED symbol.

- `lib.rs`: new `NamespaceRegistry::fn_def_names()` (the `mark_fn_def` pairs).
- `evaluator.rs::Environment::function_names()`: for each fn-def mark whose bare name is a
  `UserFn` in `engine_fns`, push the qualified `ns:name`.
- Verified: port `foo:a 100` → `101`; bare `a 100` still strands (oracle: unassigned).
