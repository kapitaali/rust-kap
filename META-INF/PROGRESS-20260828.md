## DONE today

### `⟦ … ⟧` function-call list fully implemented (task t4)

`⟦` = Kotlin `FunctionCallOpenParen` (tokeniser.kt:480); `⟧` = `FunctionCallCloseParen`.
Handled only in `processFn` (parser.kt:440): a function immediately followed by `⟦`
parses `;`-separated contents into a single LIST argument → **monadic** call
`fn (a b c)`. It is NOT a standalone bracket and NOT dyadic (oracle: `g ⇐ {⍺+⍵} ⋄ g⟦10;20⟧`
→ "Variable not assigned: kap:⍺", proving ⍵=(10 20), ⍺ unbound).

Oracle verdicts (verbatim):
- `g ⇐ {⍵} ⋄ g⟦1;2;3⟧` → `⊢ ╔═╤═╤═╗`
- `g⟦⟧` → `⊢ ╔⊖╗` (empty list)
- `g⟦42⟧` → `⊢ 42`
- top-level `⟦+;1;2⟧` → `⊢ Error at: 1:1: Unexpected token: FunctionCallOpenParen`

Files edited: `kap-core/src/token.rs`, `kap-core/src/lexer.rs`, `kap-core/src/parser.rs`.

1. **token.rs** — added `FunctionCallOpenParen` / `FunctionCallCloseParen` variants
   (after `MemberDereferenceToken`).
2. **lexer.rs** `single_char_token` — `'⟦' => FunctionCallOpenParen`,
   `'⟧' => FunctionCallCloseParen`.
3. **parser.rs** new helper `parse_function_call_list(&mut self, fn_instr: Instr)`:
   consume `⟦`; push `FunctionCallCloseParen` on `kotlin_close_stack`; loop `parse_expr()`
   items separated by `;`; empty `⟦⟧` → empty `Array`; returns
   `Apply { fn_expr, left: None, right: Array[elements] }` (monadic). On error, pop the
   close stack before returning. Borrow-checker fix (E0502): extract `next_kind: Option<Token>`
   into an owned value before `kotlin_close_stack.pop()`.
4. **parser.rs `finish_fn_call`** — after `bind_operators_kotlin`, if next token is
   `FunctionCallOpenParen`, delegate to `parse_function_call_list`.
5. **parser.rs `parse_apply`** — after `first = parse_primary()`, if `is_function_expr(first)`
   && next is `FunctionCallOpenParen`, `return parse_function_call_list(first)` (fixes the
   paren-group form `(g⟦a;b⟧)` which formerly routed through legacy `parse_apply`).
6. **parser.rs `parse_primary`** — `FunctionCallOpenParen` arm →
   `Err("unexpected token: function-call bracket ⟦ (must follow a function)")`
   (top-level `⟦` error, matches oracle intent).
7. **parser.rs `parse_value_kotlin`** — `LambdaToken` arm: advance, `parse_function_atom`,
   `finish_fn_call` (fixes `λ` inside a `⟦` list — was hitting the catch-all reset loop).

### Bug found & fixed during probing

In `parse_apply`'s leading-symbol monadic-apply heuristic, `next_is_operand_not_fn`
did NOT exclude `Token::FunctionCallCloseParen` (nor `FunctionCallOpenParen`). A defined
function symbol (in `known_functions` via `⇐`) followed by `⟧` was treated as a monadic
operand and `parse_apply()` was called on `⟧` → "unexpected token in primary".

- Only tripped for **defined** symbols as `⟦` elements (undefined → `is_known` false → strand;
  literals → Symbol branch skipped).
- Fix: added `&& !matches!(t, Token::FunctionCallCloseParen)` and `FunctionCallOpenParen`
  to the operand-exclusion list, so a leading function inside `⟦ … ⟧` stops at `⟧`.
