### const-in-function (`assignmentToConstInFunction`)

Kotlin binds constness to the *storage cell* (`StackStorageDescriptor.isConst`,
`parser.kt:32`), not to a name in a namespace table. `AssignmentInstruction.make`
(`instr.kt:510`) throws at PARSE time — so `declare(:const a)` poisons the binding
before any call, and even the no-call program errors (`kind:fails`, `expected=None`).
The port's `declare_const` is a runtime `(ns,name)` set in `ns_registry` +
`check_not_constant` at `Instr::Assign` eval (`evaluator.rs:844`) — so the no-call
program evaluates to `0`. Per PLAN §0.4 the corruption is in the *extraction*,
not the fix direction; per TDD the fix is a parse-time const-mark on the binding
(`findEnvironmentBinding`-equivalent), verified RED first via the no-call program
(port `0` vs Kotlin `assertFailsWith`). Fix NOT attempted this session (Rule of Three
budget reserved for the operator pair below).

### axis-across-envs (`axisAssignedFunctionWithDifferentEnv3`)

Kotlin `parseOperator` (`parser.kt:1280`) wraps `+[y]` in
`AxisValAssignedFunctionDirect` capturing `axisBindEnv = currentEnvironment()`
when `subtreeHasLocalBindings()`. The `{…} 0` block + `∇ foo` push *closed*
environments; the axis `y` (bound in the throwaway block scope) cannot be
`bindRemote`d across them, so `makeVariableRef` → `findEnvironmentBinding` fails
and the program errors (`InvalidOperatorArgument` per the test's `assertFailsWith`).
The port's `Instr::AxisApplied` evaluates the axis Instr *lazily at apply time*
in the caller's dynamic scope (`eval_apply`, `evaluator.rs:1789`), where `y ← 1`
is still visible — so `+[y]` silently works and `(4 5 6)` results. Bisected:
`abc ⇐ {+[y] ⍵} ⋄ y ← 1 ⋄ abc¨ 4 5 6` → `(4 5 6)` both with and without the
`{…} 0` wrapper, i.e. the port never enforces closed-env capture at all.
Both sibling tests (`…Env1/Env2`, unclosed scope) legitimately pass in both
implementations; only the `{…} 0`-wrapped `…Env3` must fail. Fix direction:
capture axis/free vars at `⇐`/`∇` bind time (closure env), not at apply time.
NOT attempted this session — same shared capture machinery as the operator pair.
