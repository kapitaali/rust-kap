## Fix 1 — dyadic `defer` (`simpleLazyEvaluation2Arg`, +1 OK)

**Symptom:** `((100 foo defer 10) (100 foo defer 20) (100 foo defer 30))[2]`
with dyadic `∇ (a) foo (b)` died with
`parse error: Index dereference without argument` at the `[2]`.
Oracle: `30135` (prints `30`, result `135`).

**Root cause:** Kotlin `processFn` (parser.kt:432) calls `parseOperator(fn)`
FIRST — `defer` binds to `foo` as a pure operator (no value operand), and the
`10` is parsed AFTER as the call's right arg
(`FunctionCall2Arg(derived, 100, 10)`). The port's `bind_operators_kotlin`
`defer` arm instead consumes `defer v` eagerly into
`ValueOp{func, defer, operand}`, so `finish_fn_call(foo, left=[100])` saw no
right arg and built a left-bind `Train[100, ValueOp]`; the stranded Trains
then left `[2]` to be misread as a right arg.

**Fix** (`kap-core/src/parser.rs`, `finish_fn_call` `!has_right` branch): a
`defer`-ValueOp with non-empty left builds
`Apply{fn: ValueOp{foo,defer,10}, left: bound, right: Empty}` instead of a
left-bind Train. The dummy `Empty` right is never evaluated — the evaluator's
`defer` arm (evaluator.rs:3371) builds `Apply{func, left, operand}` from the
ValueOp parts and ignores apply-time `right` (verified: no forcing of
left/right precedes the ValueOp dispatch at evaluator.rs:3325).

Monadic path untouched (`left_args.is_empty()` returns the ValueOp as-is;
yesterday's `d7d06fe` stranding still applies).

**Oracle transcripts** (kap-jvm-text `--no-standard-lib --no-lineeditor`,
single-line `⋄`-joined; multi-line stdin misparses — known REPL artifact):
- `∇ (a) foo (b) { io:print b ⋄ a + b + 5 } ⋄ ((100 foo defer 10) (100 foo defer 20) (100 foo defer 30))[2]`
  → oracle `⊢ 30135`, port `30135` ✓ (exact)
- NEG `simpleLazyEvaluationFailsWith2Arg` (monadic foo, `1 foo defer 10`):
  oracle arity error, port arity error ✓
- NEG `simpleLazyEvaluation2ArgFailsWith1Arg` (dyadic foo, `foo defer 10`):
  oracle prints `30` then `Variable not assigned: default:a`,
  port prints `30` then `undefined symbol: a` ✓ (same observable behavior)

## Fix 2 — `deferWithCollapseAndDiscard` (+1 OK, DeferComputationTest 8/8)

**Symptom:** `⊣ io:print defer 1 2 3` died with
`parse error: No arguments specified for function`. Oracle: `⍬`, empty out.

**Root causes (two):**
1. Parser: `nested_right_is_fn_result` fell through to `is_function_expr`,
   which counts `ValueOp` as function-shaped — so the `defer`-ValueOp right
   arg built `Train[⊣, ValueOp]` (Chain2) instead of `Apply`. But a
   `defer`-ValueOp is an applied VALUE (`DeferredAPLValue` extends
   `APLArray`), i.e. Kotlin `InstrParseResult`, never `FnParseResult`.
   Fix: early `return false` for `ValueOp{defer}` (other ValueOps
   `⍤⍣⍢proto` stay function-shaped).
2. Evaluator: the native-fn dispatch (evaluator.rs:3734) forced `right`
   eagerly — detonating the deferred call for its side effects. Kotlin
   `HideAPLFunction.eval1Arg` discards the arg value untouched. Fix: monadic
   `⊣` (`name == "⊣" && left.is_none()`) evaluates `right` WITHOUT `.force()`
   and returns `Null`. Dyadic `⊣` unchanged.

**Oracle transcripts** (grounding the eval-without-force semantics):
- `⊣ io:print 5` → oracle `⊢ 5⍬`, port `5⍬` ✓ (eager arg runs, then discarded)
- `⊣ io:print defer 1 2 3` → oracle `⊢ ⍬` silent, port `⍬` silent ✓

## Fix 4 — Str↔char-array content equality in all three compare fns (value bug, no count change)

Kotlin `APLArray.compareEqualsTotalOrdering` (types.kt): `APLString` IS an
`APLArray`, so String-vs-char-array compares by dimensions + pairwise
`valueAt`, storage-blind, for every type-discrimination flag. The port's
`total_equal` (≡ path), `type_equal` (∊/map keys) and `deep_equal` (= scalar
path) all fell through to `_ => false`.

New `str_chars_equal` helper + symmetric arms in all three fns. Oracle transcripts:
- `(("A",@y,")") ≡ "(Ay)")` → 1/1 ✓ (was 0/1)
- `((@x,@y) ≡ "xy")` → 1/1 ✓, `((@x @y) ≡ "xy")` → 1/1 ✓ (strand had it too)
- `(@y ≡ "y")` → 0/0 ✓ (rank differs — arm correctly rejects)
- `=` element-wise paths unchanged (`(1 1)` both)
