## Fix 1 — dyadic `defer` (`simpleLazyEvaluation2Arg`, +1 OK)

**Symptom:** `((100 foo defer 10) (100 foo defer 20) (100 foo defer 30))[2]`
with dyadic `∇ (a) foo (b)` died with
`parse error: Index dereference without argument` at the `[2]`.
Oracle: `30135` (prints `30`, result `135`).

**Root cause:** Kotlin `processFn` (parser.kt:432) calls `parseOperator(fn)`
FIRST — `defer` binds to `foo` as a pure operator (no value operand), and the
`10` is parsed AFTER as the call's right arg
(`FunctionCall2Arg(derived, 100, 10)`). The port's `bind_operators_kotlin`
`defer` arm instead consumes `defer v` eagerly into
`ValueOp{func, defer, operand}`, so `finish_fn_call(foo, left=[100])` saw no
right arg and built a left-bind `Train[100, ValueOp]`; the stranded Trains
then left `[2]` to be misread as a right arg.

**Fix** (`kap-core/src/parser.rs`, `finish_fn_call` `!has_right` branch): a
`defer`-ValueOp with non-empty left builds
`Apply{fn: ValueOp{foo,defer,10}, left: bound, right: Empty}` instead of a
left-bind Train. The dummy `Empty` right is never evaluated — the evaluator's
`defer` arm (evaluator.rs:3371) builds `Apply{func, left, operand}` from the
ValueOp parts and ignores apply-time `right` (verified: no forcing of
left/right precedes the ValueOp dispatch at evaluator.rs:3325).

Monadic path untouched (`left_args.is_empty()` returns the ValueOp as-is;
yesterday's `d7d06fe` stranding still applies).

**Oracle transcripts** (kap-jvm-text `--no-standard-lib --no-lineeditor`,
single-line `⋄`-joined; multi-line stdin misparses — known REPL artifact):
- `∇ (a) foo (b) { io:print b ⋄ a + b + 5 } ⋄ ((100 foo defer 10) (100 foo defer 20) (100 foo defer 30))[2]`
  → oracle `⊢ 30135`, port `30135` ✓ (exact)
- NEG `simpleLazyEvaluationFailsWith2Arg` (monadic foo, `1 foo defer 10`):
  oracle arity error, port arity error ✓
- NEG `simpleLazyEvaluation2ArgFailsWith1Arg` (dyadic foo, `foo defer 10`):
  oracle prints `30` then `Variable not assigned: default:a`,
  port prints `30` then `undefined symbol: a` ✓ (same observable behavior)

## XmlParserTest round 3 — 2987/2987, corpus at 100%

Three parser-level root causes, all Kotlin-ground-truthed, closed the last 9 rows:

1. **Symbol literals intern into the CURRENT namespace** — new
   `Parser::intern_symbol_ns` in `parser.rs`, applied at the four literal sites
   (`LiteralValue::SymbolValue` in both value parsers, `Instr::SymbolValue`, and
   both QuotePrefix arms). Kotlin `engine.nameToSymbol` (engine.kt:574-581 →
   `findSymbolInImportsOrIntern` engine.kt:1003) interns a namespace-less name
   into the namespace in effect where it is READ, so `'getLength` inside
   `namespace("xml")` IS the symbol `xml:getLength` — the same one
   `⍺.xml:getLength` dereferences, which is what makes xml.kap's
   `map:with \`'getLength λ{…}` dispatch table resolve. Oracle-verified:
   `io:print 'bar` in a root session → `default:bar` (the port used to print
   bare `bar`), and inside `namespace("foo")` → `foo:bar`. An explicitly
   qualified `'kap:array` keeps its namespace. Note `map:with`'s key rule is
   `makeTypeQualifiedKey()` = the key value itself (builtins/map.kt:5-32) — there
   is no special interning in the native; the whole difference is parse-time.
2. **Method-call names get the same treatment** — `Token::MethodCallToken` in the
   main accumulator now runs the bare method name through `intern_symbol_ns`,
   because Kotlin's `tokeniser.nextSymbol()` is `engine.nameToSymbol`
   (tokeniser.kt:499-501). Without it `nodeList⍠getLength` looked up
   `Symbol{None,getLength}` against keys now correctly stamped `xml:getLength`
   ("Method not found: default:getLength").
3. **`object.member` is NOT function-shaped** — removed
   `Instr::MemberDeref` from `is_function_expr`. Kotlin's
   `MemberDereferenceInstruction` / `MemberDereferenceNameArgumentInstruction`
   extend `Instruction` (lookup.kt:18/57) and `processMemberDereference` returns
   a plain `TokenParseResult.Instr` (parser.kt:1013) — a VALUE operand. Treating
   it as a function made the right-arg parse classify the deref as an atop/Chain2
   argument (`nested_right_is_fn_result` → `is_function_expr`), so
   `io:print a.b`, `⊂a.(3)` and `1+a.(3)` all died on the statement-level
   bare-function check ("No arguments specified for function"). Verified:
   `a ← 10 20 30 40 ⋄ io:print a.(3)` → `40 40`, oracle `4040`. This one fix
   flipped nodeTypes + testNodeText + the four XPath rows.
4. **`jvm:isJvmNull`** (the last row, `testAttributes`) — Kotlin
   `IsJvmNullFunction` (jvm-module.kt:551-558) is monadic 1/0: 1 iff the argument
   is `APLNilValue`. The bridge already produces exactly that for a Java `null`
   return (`JVal::Null | JVal::Void => APLValue::Nil`, evaluator.rs:8894), so the
   new arm is `matches!(v.as_ref(), APLValue::Nil)`. Registered in all three
   gates (parser `is_known_fn` jvm list, both evaluator `is_primitive_name`
   lists). xml.kap:131 uses it on `getAttributes()`; probe
   `work/probe_xmlattr.kap` now prints the attribute pairs
   `(a 123 b some text)` from `test-data/foo.xml`.
