  `[f, g]` atop → `g˝(f˝ a)` (Kotlin Chain2.evalInverse1Arg, instr.kt:600).

  `×` dyadic left-bound → `right ÷ left` (Mul evalInverse2ArgB = b÷a); monadic `×` errors.

### (3) `KapNumber::sub` mixed-type operand-order bug  [FIX — pre-existing, broader than ˝]
`sub` (number.rs) combined `(Long,Double)|(Double,Long)` arms and reused `self`'s
binding `a` for the non-`self` operand, so `Double - Long` computed `Long - Double`.
Affected ALL mixed Long/Double/BigInt/Rational/Complex subtraction (e.g. `4.5 - 3`
gave `¯1.5`). Split every combined arm into two with correct `self - other` order.
Kotlin ground truth: `SubAPLFunction.evalInverse2ArgB(a,b)=a-b`,
`evalInverse2ArgA(a,b)=a+b` (math_functions.kt:734/738).

### (4) `⍨` commute inverse in `adverb_inverse`  [FIX — new arm]
Added `Instr::Derived{op:⍨}` arm: `(v f⍨)˝ a = f.evalInverse2ArgA(a, v)`
(Kotlin CommuteFunctionImpl.evalInverse2ArgB/A, commute.kt:24-32; has NO
evalInverse1Arg, so monadic `(f⍨)˝ y` errors). For `+ - × ÷` computed directly:
`+`→`a-v`, `-`→`a+v`, `×`→`a÷v`, `÷`→`a×v`. Nested trains recurse on A-path.

### Defect 1 — parser silently dropped `˝` through an enclosing paren group

### Defect 2 — evaluator `adverb_inverse` lacked train + scalar-inverse support
Kotlin ground truth located (READ-ONLY `~/Apps/array/array`):
- Trains are `FunctionCallChain` (instr.kt): `Chain2` (2-train/atop) **implements**
  `evalInverse1Arg = fn1.inv(fn0.inv(a))` (instr.kt:600); `Chain3` (3-train fork)
  does **NOT** → inherits the base-class throw ("Function does not have an inverse").
  `(1+2×)` is a `Chain2` of two left-binds (not a fork) — that is why the oracle

**Fix (`adverb_inverse`, evaluator.rs ~5413-5613):**
- Added `Instr::Train` arm: 2-member `[value, fn]` left-bind → recurse with
  `left=Some(value)`; 2-member `[f, g]` atop → `g˝(f˝ a)`; 3+ member → error.
- `-` now forwards in both monadic and left-bound forms (self-inverse).
- `+`/`÷` monadic forward (identity/self-inverse); dyadic left-bound inverts with
  correct operand order (`+`: `a-left`; `÷`: `left×a` per Div `evalInverse2ArgA`).
- `×` dyadic left-bound → `right ÷ left` (Mul `evalInverse2ArgB` = `b÷a`); monadic
  errors ("Function does not have an inverse").
- Error text aligned to Kotlin: `<fn>: Function does not have an inverse`.

## Bitwise `∵` adverb repair (P4-3) — committed after `2b87555`

**Oracle ground truth** (`~/Apps/array/kap-jvm-text`, never ran Gradle). Kotlin
`BitwiseOp` (bitwise_ops.kt:55) calls `fn.deriveBitwise()` per scalar fn; the
resulting operation is the *verified* table below (probed, not inferred):

| glyph | dyadic | monadic |

| `+` `≠` `-` | XOR `a^b` | error |
| `=` | XNOR `!(a^b)` | error |

| `~` | — | NOT `~b` |

"`∵: Function cannot be called with one argument`". Non-integer operands ⇒

**preserving array nesting** (`~∵ (1 2 3)` ⇒ `⟨-2 -3 -4⟩`;
`⍸∵ (0 1 b) (0 0 255)` ⇒ `⟨⟨0 1 4⟩ ⟨0 0 8⟩⟩`).

## `˝` inverse adverb — second repair pass (after `33d3700`)

The first `˝` pass left a cluster of wrong-answer/error-class mismatches in the
conformance sweep. Confirmed against the Kotlin oracle via AST dump (eprintln
debug, removed after):

**Bug A — `÷` left-bound inverse was inverted.** `(v÷)˝ a` computed `v × a`
(e.g. `128 ÷˝ 4 → 512`) instead of `v ÷ a` (`→ 32`). The `÷` arm wrongly
forwarded `×`. Fixed: `(v÷)˝ a` ⇒ `v ÷ a` (Div `evalInverse2ArgB` = `b ÷ a`).
Oracle: `128 ÷˝ 4→32`, `4 ÷˝ 16→1/4`, `(10÷)˝ 5→2`, `(÷)˝ 8→1/8`. This also
unblocked the chain-inverse cases that recurse into `(200÷)˝`:
`(2+200÷)˝ 6→50`, `((2+)(200÷))˝ 6→50` (oracle match).

**Bug B — left-bound `((1+)˝)` called dyadically must error.** `7 ((1+)˝) 8`
returned `7` (ignored the leading `7`); oracle errors
"`+: Left assigned functions cannot be called with two arguments`". `(v f)˝` is
already left-assigned; a further left arg ⇒ 2-arg call ⇒ error. Added guard in
the `Train` arm: if `funcs[0]` is a value AND `left.is_some()` ⇒ that error.

**Bug C — `∘`/`⍛` compose have no inverse.** `(+∘-)˝ 1` returned `¯1`;
`(+⍛-)˝ 1` returned wrong too. Kotlin's `ComposedFunction`/`ReverseComposedFunction`
define no `evalInverse*`. Added guard: `compose:true` ⇒ error
"`∘: Function does not have an inverse`"; `compose:true && reverse:true` (⍛) ⇒
"`⍛: Function does not have an inverse`" (verified via AST dump: ⍛ parses as
`Train{funcs:[f,g], reverse:true, compose:true}`, ∘ as `compose:true` only).

**Verified (9 cases, error-text matches oracle modulo the cosmetic `error:` vs
`Error at: 1:N:` prefix):** `128÷˝4→32`, `4÷˝16→1/4`, `(10÷)˝5→2`, `(÷)˝8→1/8`,
`(2+200÷)˝6→50`, `((2+)(200÷))˝6→50`, `(+∘-)˝1` error, `(+⍛-)˝1` error,
`7 ((1+)˝) 8` error.

**Gates:** 96/0 lib; 1/0 curated. No new probe script added (debug print removed).

## ScalarTest `*` / `⌈` / `⌊` parity — committed after `f252515`

Next conformance cluster after `∵`+`˝`: regenerated the per-case dump, aggregated
mismatches by source file, and picked `ScalarTest.kt` (13 mismatches = 3 distinct
self-contained value-correctness bugs). All 13 now match the Kotlin oracle (the
`error:` vs `Error at: 1:N:` prefix is cosmetic — the harness normalizes it).

### Bug 1 — `*` (power) integer-overflow + exact BigInt + negative-power rationals
- `10*100` previously returned `9223372036854775807` (i64 saturating_pow overflow);
  oracle returns the exact 101-digit BigInt. Fix: `pow` (number.rs:581) now computes
  integer∧non-neg-integer via `BigInt::pow`, reduced to Long when it fits
  (`bigint_to_kap`), else kept as BigInt. `10*100`/`10*1000` → exact.
- `10*1234567890123457` (and the 39-digit, negated variants) previously returned
  `Infinity`/`0.0`. Oracle errors "`*: Value does not fit in an int: <exp>`". Fix:
  the `*` arm (evaluator.rs:2541) detects an integer base ∧ integer exponent whose
  magnitude exceeds u32 and errors with the raw exponent rendered via the new
  `KapNumber` `Display` impl (plain ASCII minus, matches oracle text). Covers both
  `Long` and `BigInt` bases (the 39-digit base had a BigInt base + BigInt exponent).
- `2*¯3` (and `2⋆¯1`) previously returned `0.125`/`0.5` (Double). Oracle keeps exact
  rationals: `1/8` / `1/2`. Fix: negative integer power of an integer base now yields
  `Rational(1 / base^|exp|)`.

### Bug 2 — `⌈` / `⌊` char & complex & non-finite rejection
- `@a⌈1` / `@a⌊1` previously passed the char through (returned `@b`). Oracle errors
  "`⌈: Incompatible argument types. Left arg: char, Right arg: integer`". Fix: new
  `ceil_floor_dyadic` (evaluator.rs:9851) rejects a char on either side with the
  Kotlin text (right-arg type name derived from the KapNumber variant).
- `⌈1j2` previously returned `1.0J+2.0` (complex passed through). Oracle errors
  "`⌈: Ceiling is not valid for complex values`". `⌊1j2` →
  "`⌊: Function does not support arguments of type: complex`". Fix: new
  `ceil_floor_monadic` (evaluator.rs:9778) rejects complex for both `⌈`/`⌊`
  (distinct oracle texts).
- `⌈3.0÷0.0` / `⌊3.0÷0.0` (`Infinity`) → oracle
  "`⌈: Argument is not finite: Infinity`". Fix: `ceil_floor_monadic` errors on a
  non-finite Double with the Kotlin text (sign rendered as `¯Infinity`).
- `⌈0.0÷0.0` / `⌊0.0÷0.0` (`NaN`) → oracle returns `0`. Fix: `ceil_floor_monadic`
  normalizes a NaN Double to `Long(0)`.
