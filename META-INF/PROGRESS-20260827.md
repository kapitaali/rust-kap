## Root cause (two compounding faults in `parse_paren_accum` value-stranding arm)
A fork tine `((⌈arrayMaxWidth[0]÷⍺)↑[k])` is a parenthesised group parsed via
`parse_primary → parse_paren_vfn_chain → parse_paren_accum`. Its value arm:
1. stranded a variable as a bare token and **never consumed the trailing `[…]`**
   → `parse_function_atom` rejected `OpenBracket` at the dangling selector
   (`parse error at 1:68: unexpected token in primary`);
2. wrapped the variable as `Instr::Literal(LiteralValue::Symbol{..})` (a *literal*
   symbol) → eval rejects it with `lone symbol literal`. A reference must be
   `Instr::Symbol{name, namespace}` (lookup form).

### Minimal trigger (oracle proves only the indexed var fails; constants pass)
`a←1 2 3 ⋄ ((⌈a[0]÷2)↑[0])«,»((-⌈a[1]÷2)↑[0]) ⍳6` → oracle `⟨0 5⟩`; now port matches.
Constant analogue `((⌈80÷2)↑[0])«,»((-⌈24÷2)↑[0]) ⍳6` already passed (= oracle).

## The fix (kap-core/src/parser.rs — `parse_paren_accum` value arm)
Mirror `parse_primary`: emit `Instr::Symbol{name, namespace}` for a `Symbol`/`SymbolValue`
token (NOT `Instr::Literal`), and call `parse_index_suffix(v)` on every value literal to
fold the trailing `[…]` into an `Index`. Verified `a[0]` at top level still = oracle.

## False lead (explicitly rejected — do NOT re-add)
Extending `parse_function_atom`'s `Symbol` arm to consume `[…]` via `parse_index_suffix`
broke axis binding: `↑[0]` became `Index{↑,[0]}` instead of `AxisApplied{↑,0}` →
`only symbol/lambda functions supported yet` at eval. Axis must stay in the
`parse_paren_accum`/`parse_apply` → `bind_operators_kotlin` path. Reverted.
