## What landed
Implemented Kap's `comp` (Kotlin `CompFunction`, `div_functions.kt:76` → `a.collapse()` →
`APLArray.collapseInt` / `CollapsedArrayImpl.make` in `types.kt`). Monadic only; two-gate

### Semantics (READ from Kotlin, not guessed)
`collapseInt(withDiscard=false)`:
- rank-0 array → `EnclosedAPLValue.make(valueAt(0).collapse())` — disclose the single boxed
  element, collapse THAT, then RE-ENCLOSE it. Re-enclose is a no-op for atoms/Null, so:
  `comp ⍬ → ⍬`, `comp ⊂ 1 2 3 → ⟨⟨1 2 3⟩⟩` (a rank-0 box), `comp ⊂⊂ 1 2 3` → depth 3.
- rank>0 array → `CollapsedArrayImpl.make(v)` — preserve outer dims, collapse each inner
  element once: `comp 1 2 3 → ⟨1 2 3⟩`, `comp (1 2)(3 4) → ⟨⟨1 2⟩ ⟨3 4⟩⟩`,
  `comp 3 0 ⍴ 3` keeps shape `⟨3 0⟩`.
- non-array (scalar/string/Null) → identity.

First draft got depth wrong (disclosed the box WITHOUT re-enclosing). Fixed by routing the
rank-0 branch through `self.enclose(self.collapse(inner)?)`. Verified every probe below matches
the oracle byte-for-byte.

## Root cause (corrected from addendum-3 speculation)
Addendum 3 guessed the failure was a "fork/axis-loss in `apply_under_op`". The actual
bug: `parse_function_atom` (parser.rs:4722) — called for the `⍢` operand at

axis-eligible `Symbol` (`+ - × ÷ * , ⍪ ⌽ ⊖ ↑ ↓`), wrap it in `Instr::AxisApplied{func,
axis}`. This also benefits any other operator that parses its operand via
`parse_function_atom` and accepts an axis (e.g. `⍤` rank of an axis-qualified fn).

# PROGRESS-20260831 (addendum 6) — composite take/drop under (chained `⍢` wrapper)

**Gates (GREEN):** lib 96/0, curated 1/0, build clean.

## What landed
`apply_under_op` (`evaluator.rs:9203`) gained a 2-train COMPOSE-under path that
handles chained structural-under wrappers of the form `Train[f0, f1]`
(`(f0 f1)`, e.g. `(¯1↑¯1↓)`, `(3↑5↓)`, `(0↑5↓)`). It implements Kotlin's nested
`structuralUnder` reduction
`Chain2(f0,f1).under(base,a) = f1.under( λx. f0.under(base,x), a )`:

1. Inner: `f0.under(base, f1(a))` — recursive `apply_under_op` call (reuses the
   same take/drop/identity leaf machinery), producing the transformed inner result
   over `f1`'s selected region.
2. Outer: `f1`'s selected region of `a` is resolved to `(sel_dims, offset)` via
   `under_take_drop_spec(f1)` (take → keep leading `c`, drop → `n−c` trailing),
   then the spliced-in replacement is overlaid with `overlay_replacement`.

Supporting helpers added:
- `deep_flatten` (`evaluator.rs`): one-level flat ravel of an `AplRef` matching
  `overlay_replacement`'s expectation that `replacement` is flat-raveled like `src`.
- `is_under_compose_leaf` (`evaluator.rs`): gates the 2-train block entry on BOTH
  `f0` and `f1` being structural-under leaves (bare/axis/left-bound `↑`/`↓`, or
  `⊢`/`⊣`). Anything else (reshape, generic inverse) falls through to the existing
  reshape/inverse paths so we don't regress cases the inverse machinery already
  handles — this fixed the `(3+)⍢(1↑2 2⍴)` regression from the first draft.

The replacement is built with `make_simple_or_nested(inner_dims, inner_flat)` (flat
ravel), NOT `build_nested` (which re-nests rows and breaks `overlay_replacement`'s
one-level flat read).

## What landed

- `resolve_under_leaf_name(f, env)` — follows `a ⇐ ↑` (stored as
