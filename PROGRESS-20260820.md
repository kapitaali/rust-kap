## [2026-08-20] Fix: `cargo test` / broad conformance "hang" (O(total²) in reduce/scan)

The user reported `cargo test` froze and never printed harness results. Root cause
(confirmed, not a guess): the broad `run_kotlin_conformance` sweep iterates ~2,535
extracted Kotlin cases through the engine; ONE case triggered a **runaway**
evaluation that spins at 100% CPU forever (a HANG, not a panic — `catch_unwind`
cannot stop it), which froze the entire `cargo test`.

The offending case: `-/ 100000 ⍴ 100000000000000`.

### Diagnosis
- `adverb_reduce` (plain branch) and `adverb_scan` both called
  `data.value_at(f)` *inside* their `for f in 0..total` loops.
- `value_at` calls `APLValue::Array::elements()`, which **rebuilds the entire
  `Vec<AplRef<APLValue>>` on every call** (see `array.rs::elements`). So each
  `value_at` is O(total) → the loops became **O(total²)**.
- Timing matched: 100→4ms, 1k→48ms, 10k→4.2s, 100k→>15s (timeout). Pure quadratic.

### Fix
- Added `APLValue::elements(&self) -> Vec<AplRef<APLValue>>` in `lib.rs`
  (mirrors `value_at`, but works on scalars/strings too).
- In both `adverb_reduce` and `adverb_scan`, hoisted `let elems = data.elements();`
  ONCE outside the loop, and indexed `elems[...]` inside. Now O(total).

### Verification
- `-/ 100000 ⍴ 1` now 0.18s; `-/ 200000 ⍴ 1` 0.53s (was >15s hang).
- Re-ran the whole corpus (2,535 cases) with a 2s/case timeout: **0 hangers**
  (previously 1). The real runaway is gone, not just masked.
- Correctness preserved: `×/ 1 2 3 4 5`→120, `+⍀ 1 2 3 4`→(1 3 6 10),
  `×⌿ 3 3⍴⍳9`→(0 28 80), `+⌿ 3 3⍴⍳9`→(9 12 15), `+⌿ 100000 ⍴⍳2`→50000.
- Gates green: `cargo test -p kap-core --lib` → 92 passed, 0 failed;
  `cargo test -p kap-core --test conformance` → 1 passed (curated), 1 ignored.

### Note on the earlier `#[ignore]` workaround
`run_kotlin_conformance` was previously marked `#[ignore]` (commit 4cb614e) as a
stopgap so `cargo test` would at least print the lib/curated results. This O(n²)
fix removes the underlying runaway, so the sweep *can* run on demand
(`-- --ignored run_kotlin_conformance`) and complete. Per the skill's authority, we
keep `#[ignore]` in place for the default `cargo test` (a future incomplete
builtin could still hang); the broad sweep is opt-in. Do NOT remove `#[ignore]`.

### Files changed
- `kap-core/src/lib.rs` — added `APLValue::elements()`.
- `kap-core/src/evaluator.rs` — hoisted `elements()` out of the reduce/scan loops.

### What changed (all in `kap-core/tests/conformance.rs`)

  preserves the skill's hang-safety intent while obeying the override to run by default.
