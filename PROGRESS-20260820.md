## [2026-08-20] Fix: `cargo test` / broad conformance "hang" (O(total²) in reduce/scan)

The user reported `cargo test` froze and never printed harness results. Root cause
(confirmed, not a guess): the broad `run_kotlin_conformance` sweep iterates ~2,535
extracted Kotlin cases through the engine; ONE case triggered a **runaway**
evaluation that spins at 100% CPU forever (a HANG, not a panic — `catch_unwind`
cannot stop it), which froze the entire `cargo test`.

The offending case: `-/ 100000 ⍴ 100000000000000`.

### Diagnosis
- `adverb_reduce` (plain branch) and `adverb_scan` both called
  `data.value_at(f)` *inside* their `for f in 0..total` loops.
- `value_at` calls `APLValue::Array::elements()`, which **rebuilds the entire
  `Vec<AplRef<APLValue>>` on every call** (see `array.rs::elements`). So each
  `value_at` is O(total) → the loops became **O(total²)**.
- Timing matched: 100→4ms, 1k→48ms, 10k→4.2s, 100k→>15s (timeout). Pure quadratic.

### Fix
- Added `APLValue::elements(&self) -> Vec<AplRef<APLValue>>` in `lib.rs`
  (mirrors `value_at`, but works on scalars/strings too).
- In both `adverb_reduce` and `adverb_scan`, hoisted `let elems = data.elements();`
  ONCE outside the loop, and indexed `elems[...]` inside. Now O(total).

### Verification
- `-/ 100000 ⍴ 1` now 0.18s; `-/ 200000 ⍴ 1` 0.53s (was >15s hang).
- Re-ran the whole corpus (2,535 cases) with a 2s/case timeout: **0 hangers**
  (previously 1). The real runaway is gone, not just masked.
- Correctness preserved: `×/ 1 2 3 4 5`→120, `+⍀ 1 2 3 4`→(1 3 6 10),
  `×⌿ 3 3⍴⍳9`→(0 28 80), `+⌿ 3 3⍴⍳9`→(9 12 15), `+⌿ 100000 ⍴⍳2`→50000.
- Gates green: `cargo test -p kap-core --lib` → 92 passed, 0 failed;
  `cargo test -p kap-core --test conformance` → 1 passed (curated), 1 ignored.

### Note on the earlier `#[ignore]` workaround
`run_kotlin_conformance` was previously marked `#[ignore]` (commit 4cb614e) as a
stopgap so `cargo test` would at least print the lib/curated results. This O(n²)
fix removes the underlying runaway, so the sweep *can* run on demand
(`-- --ignored run_kotlin_conformance`) and complete. Per the skill's authority, we
keep `#[ignore]` in place for the default `cargo test` (a future incomplete
builtin could still hang); the broad sweep is opt-in. Do NOT remove `#[ignore]`.

### Files changed
- `kap-core/src/lib.rs` — added `APLValue::elements()`.
- `kap-core/src/evaluator.rs` — hoisted `elements()` out of the reduce/scan loops.

## [2026-08-20] Strings-phase: dyadic `⍳` index-of + string `cmp`

Resumed the Strings-phase work on the `strings` branch (after syncing `main` to `strings` via
`git branch -f main strings` + push, restoring the `main == strings == origin/*` invariant).

### Problem (found by mining the conformance dump, not assumed)
The dyadic `⍳` dispatch in `evaluator.rs` was `"⍳" | "iota" => self.iota(right_val)` — it
**ignored the left arg entirely**, so `L ⍳ R` ran `iota(R)` for every left arg. That made
index-of wrong for ALL types:
- `"abc" ⍳ @c` → errored ("⍳ needs an integer count")
- `"abc" ⍳ 0` → `()` instead of `3`
- `3 1 4 2 ⍳ 2` → `(0 1)` (iota of right `2`) instead of `3`
Kotlin's `FindIndexArray1DLeftArg` defines result-shape = shape of B, each element = the first
0-based index in A matching B (cross-kind `total_cmp` == Equal), else `a.size`.

Separately, `cmp_values` rejected anything but `(Number,Number)`/`(Char,Char)`, so
`"abc" cmp "bcd"` errored. Kotlin orders `number < char < string < null` and compares equal
kinds by value (`compareTotalOrdering`).

### What changed (all in `kap-core/src/evaluator.rs`)
- `⍳` dispatch is now ambivalent: monadic → `iota` (unchanged); dyadic → new `index_of(l, r)`.
- Added `index_of`: forces both args, builds an output array of shape `b.dimensions()` whose
  elements are the first match index in `a.elems()` for each `b.elems()` element, else
  `a.elems().len()` (not-found). Uses `total_cmp` for cross-kind matching.
- Extended `cmp_values` with `(Str, Str)` → `str::cmp` (lexicographic by codepoint) and a
  cross-kind `_` arm delegating to `a.total_cmp(b)` (reuses the general order: num<char<string).

### Verification (honest, against the Kotlin oracle)
- `cargo build -p kap-cli` → clean (only pre-existing `unused variable` warnings).
- REPL probes confirm exact Kotlin values:
  `"abc" ⍳ @c`→`2`, `"abc" ⍳ 0`→`3`, `3 1 4 2 ⍳ 2`→`3`, `3 1 4 2 ⍳ 9`→`4`,
  `"abc" ⍳ "xyz"`→`3 3 3`, `1 2 3 ⍳ 2 1`→`1 0`, `"abc" cmp "bcd"`→`¯1`,
  `"abc" cmp "abc"`→`0`, `"xyz" cmp "abc"`→`1`, `⍳5`→`0 1 2 3 4` (regression OK).
- Added 11 curated rows to `curated_kap_parity` (FindIndexTest + string cmp).
- `cargo test -p kap-core` → **92 lib + 2 conformance (curated + broad) + 1 doctest, all
  passed, 0 ignored, EXIT=0**. Broad sweep ran in ~3.4s (hang-proof, no regression).
- Coverage **42.2% → 43.0%** (1071 → 1091 ok over 2,535 cases). The `index_of` fix also
  repaired the entire numeric `⍳` (FindIndexTest.kt) family — they were all MISMATCH before
  because the old dispatch ran `iota` on the right arg.

### Files changed
- `kap-core/src/evaluator.rs` — ambivalent `⍳`, new `index_of`, string-aware `cmp_values`.
- `kap-core/tests/conformance.rs` — 11 curated index-of/cmp regression rows.
- `conformance_summary.txt` — regenerated (43.0% headline).
